🚀 Key Innovations

Engineering Decisions Worth The Prize

Three tradeoffs that separate us from a standard hackathon project.

🔗
Deterministic Orchestration via LangGraph — not a standard LLM agent
LangGraph forces data through strict graph nodes. Unlike a probabilistic agent, it cannot hallucinate its own reasoning path. Critical for emergency response reliability.
💧
MD5 Digital Twin IoT Simulator — not a static Kaggle CSV
The same city always generates the same sensor reading (deterministic). This proves our architecture is plug-and-play: swap the hash function for a real MQTT stream and the system works identically.
📋
Native JSON Tool Calling — not string parsing
We defined a strict JSON Schema function (submit_risk_assessment). The Groq LLM is forced to fill it in, guaranteeing our dashboard always receives perfectly structured data — zero parsing failures.
📚
RAG as a Legal Policy Engine — not a knowledge base chatbot
We use ChromaDB Vector Store to ground every AI recommendation in official WHO environmental regulations. In a government deployment, every intervention must be legally traceable to a specific policy.
📚 Deep Dive

Why RAG? Not Just an LLM Prompt?

Two engineering reasons that prove we understand the technology.

Problem 1: LLMs Hallucinate
If we ask the Groq LLM to recommend a WHO policy from memory, it might generate a plausible-sounding but completely fabricated regulation. In a government deployment, a hallucinated legal policy is a liability.
Solution: RAG Grounds the AI
Before the LLM responds, we force it to retrieve the actual policy text from ChromaDB. The LLM can only use what it found. No hallucination possible. Every recommendation is traceable.
Problem 2: Token Limits & Updateability
Pasting 1000 WHO policies into the prompt hits token limits. With ChromaDB, we store unlimited documents and retrieve only the 1-2 most relevant ones. And if WHO updates a policy tomorrow, we just update the database — no LLM retraining needed.
